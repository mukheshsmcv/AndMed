# Question Recommendation Engine

## 1. Architecture
The Intelligent Question Delivery Engine (M11) connects the student's context to the question bank through a deterministic, single-pass recommendation pipeline. It consumes intelligence generated by M6 (Adaptive), M9 (Mission), and M10 (Performance) rather than recreating them.

**Pipeline:**
Student Context → Candidate Filtering → Candidate Scoring & Tiering → Deterministic Selection → Next Question

## 2. Candidate Filtering
Before any scoring occurs, invalid candidates are strictly eliminated:
- `status` must be `PUBLISHED`.
- **Repetition Lock**: If a question was answered `< 1 day ago`, it is excluded, **UNLESS** it is flagged as an explicitly overdue revision, allowing spaced repetition to occur while blocking accidental immediate duplicates.

## 3. Priority Tiers
We respect the M9 Mission Action by assigning candidates to absolute priority tiers (Lower = Higher Priority).
- **Tier 0 (Revision)**: Triggered when `missionAction === 'REVISION'` and the candidate is in `overdueRevisionQuestionIds`.
- **Tier 1 (Weakness)**: Triggered when `missionAction === 'WEAK_AREA'` and the topic is a `CRITICAL_WEAKNESS` or `EMERGING_WEAKNESS`.
- **Tier 2 (Normal)**: Default fallback.

The engine selects the highest available tier first, then falls back to scoring within that tier.

## 4. Scoring Formula & Weights
Each candidate within the selected tier receives a score based on deterministic rules:
- **Exam Relevance**: `+ (examRelevance * 2)` (Max: 20 points).
- **Mastery-Aware Difficulty Strategy**:
  - *Cold Start / Low Mastery (< 40)*: Easy (+15), Medium (+5). Hard receives 0.
  - *Medium Mastery (40-74)*: Medium (+15), Hard (+5). Easy receives 0.
  - *High Mastery (>= 75)*: Hard (+15), Medium (+5). Easy receives 0.
- **Weakness Targeting**:
  - `CRITICAL_WEAKNESS`: +15 points
  - `EMERGING_WEAKNESS`: +10 points
  - `KNOWLEDGE_GAP`: +5 points
  - `STRONG_AREA`: -5 points (to enforce diversity and prevent over-indexing on easy wins)
- **Repetition Penalty (Diversity Strategy)**:
  - If answered within 7 days, subtracts `(7 - daysSince) * 2`. Reduces immediate re-exposure while allowing natural spaced reinforcement.

## 5. Cold-Start Strategy
For users with zero attempts:
- Topic mastery is empty.
- Priority tier defaults to Normal (Tier 2).
- Difficulty targets Easy (+10) and Medium (+5).
- Final selection relies on Exam Relevance + Deterministic ID tie-breaker, providing a consistent baseline diagnostic experience.

## 6. Tie-Breaker Strategy
If candidates tie, the following stable hierarchy is evaluated sequentially:
1. Lowest Tier (Priority)
2. Highest Score
3. Highest Exam Relevance
4. Alphabetical Question ID (Ultimate deterministic fallback)

## 7. Query Strategy
To avoid N+1 and OOM errors on large datasets:
- `/api/next-question` uses `.limit(200)` to pull a chunk of published questions.
- Context queries (`question_attempts`, `revision_items`) are similarly scoped/indexed.
- All evaluation happens in-memory in `O(N)` time relative to the subset size.

## 8. Security Model
- Identity is derived strictly from `supabaseServer.auth.getUser()`.
- Client cannot manipulate mastery, weakness, or influence the selected tier directly.
- The returned payload never contains `is_correct` or other answer-key metadata.
